# Считалка (репозиторий Wolf)

Асимметричный хоррор 4 против 1 в духе Dead by Daylight на каркасе «Десяти
негритят»: в мёртвом квартале заперты четверо не самых хороших людей, и охотится
на каждого тот, кому он однажды сделал плохо. Убийца в матче один — но их три
разных, и это три разных игры.

Дизайн целиком — `docs/GDD.md`.

## Быстрый старт: браузерный прототип

Играбельная версия всей петли, без Unity и без установки:

```
web-prototype/index.html   ← открыть в браузере
```

Внутри: квартал из руин, боты-гости с настоящей навигацией, все три убийцы
(Трикстер, Ведьма, Весёлый Роджер) с полными наборами сил, крюки, щиты, пролом и
считалка. Страница самодостаточна — ноль внешних запросов.

- `web-prototype/index.template.html` — исходник (**редактировать этот файл**)
- `web-prototype/build.js` — вклеивает three.js + GLTFLoader + персонажа
  (vendored `vendor/Soldier.glb`, MIT-лицензия из репозитория three.js) в один
  файл
- `web-prototype/index.html` — собранный результат

После правки шаблона пересобери: `cd web-prototype && node build.js`.

## Unity-проект

Этот репозиторий пишется без доступа к самому Unity Editor (headless-среда),
поэтому в нём только код (C#), а не бинарные/YAML-файлы Unity (сцены,
ProjectSettings, .meta). Их нужно сгенерировать локально один раз — дальше всё
синхронизируется через git как обычно.

### Установка (один раз)

1. **Unity Hub** → установить **Unity 2022 LTS** (любая последняя патч-версия
   2022.3.x). Именно LTS — стабильнее для WebGL.
2. При установке движка отметь модуль **WebGL Build Support**.
3. Создай новый проект: **3D (URP)** template. Название не важно, но проще всего
   создать его прямо в клоне этого репозитория, в корне (там, где лежит этот
   README) — тогда `Assets/_Project` окажется внутри проекта автоматически.
   - Если Unity создаёт проект в отдельной папке — просто скопируй содержимое
     `Assets/_Project` из репозитория в `Assets/_Project` нового проекта.
4. Открой проект, подожди импорт — Unity сам досоздаст `.meta`-файлы для всех
   скриптов, это нормально, коммить их вместе с кодом.
5. **Tools → Wolf → Build Everything** — соберёт placeholder-префабы, сцену лобби
   и блокаут квартала. После этого открой `Assets/_Project/Scenes/Lobby.unity` и
   нажми Play.
6. **Window → AI → Navigation → Bake.** Боты ходят по NavMesh; без запечённой
   навигации они свалятся на движение по прямой и будут упираться в стены
   (в браузерном прототипе для этого написана своя сетка путей, в Unity этим
   занимается NavMeshAgent).

Photon (PUN2) нужен только для мультиплеера — для матча с ботами он не
обязателен, код это учитывает (см. `INetworkService`). Если дойдёт до сетевой
игры: бесплатный аккаунт на photonengine.com → приложение типа **PUN** → App Id
в `PhotonServerSettings`.

### Структура

```
Assets/_Project/
  Scripts/
    Core/          — GameManager, состояния матча, настройки, считалка
    Networking/    — абстракция над сетью (Offline / Photon)
    Player/
      Guest/       — гость: состояния, ползание, вырывание, спасение
      Killer/      — база + Трикстер / Ведьма / Весёлый Роджер
    AI/            — боты гостей и убийц (NavMesh, если запечён)
    Objectives/    — щиты, крюки, пролом, поросль, ломаемые стены, проёмы
    Health/        — здоровье и урон
    UI/            — лобби, HUD
    Utils/
  Editor/          — сборка префабов и сцен одной кнопкой
docs/
  GDD.md           — гейм-дизайн
web-prototype/     — браузерный прототип (см. выше)
```

### WebGL-билд

`File → Build Settings → WebGL → Switch Platform → Build`. Для первого теста
скорости хватит; когда дойдём до финального билда — обсудим сжатие
(Brotli/Gzip) и хостинг.

## Статус

Петля матча собрана и играется в браузерном прототипе целиком: щиты → пролом,
погоня → на землю → крюк или казнь, спасение с крюка и подъём с земли, считалка.
Unity-версия повторяет ту же модель кодом, но сцену/арт нужно собрать локально.

Не сделано: мультиплеер на новой петле, настоящие модели и анимации (сейчас один
риг в трёх покрасках), звук сверх синтезированного в прототипе, прогрессия.
