# Dishonored Mod Kit

Инструментарий для мода к Dishonored (2012): новые режимы игры, выбор
персонажа, новые механики.

## Что нужно знать до начала

Исходников Dishonored нет — Arkane и Bethesda их не публиковали. Модифицируется
собранная игра, и делается это на трёх разных уровнях, отличающихся по цене на
порядки: текстовые конфиги, скомпилированные пакеты `.upk` и нативный код в
процессе игры. Подробный разбор — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

Полезная новость: Arkane вынесли изрядную часть геймплея в обычные текстовые
`.ini` — `AI.ini`, `Player.ini`, `Weapon.ini`, `Camera.ini`, `PlayerState.ini`.
Здоровье, урон, стоимость способностей, параметры обнаружения ИИ настраиваются
без единого бинарного инструмента.

## Состояние

| Слой | Состояние |
|---|---|
| Инструменты сбора данных | готово, разведка на живой карте завершена |
| Режимы на INI | движок готов, ждёт реальных ключей из `harvest` |
| Правки UPK | `tools/upk.py` читает пакеты игры; правка не начата |
| Нативный слой | работает: перехват, таблица имён, список объектов, патчер |
| Ролевой режим | сторона игрока меняется одной строкой конфига |

Разведка кончилась. Раскладка объектов UE3 подтверждена по живой игре, приём у
Бойл выгружен целиком — 111 830 объектов, 3045 классов, все семнадцать фракций
с содержимым массивов отношений. Дальше правки пишутся по файлам выгрузки, а не
по догадкам, и каждая новая не требует ещё одного захода в игру.

Ролевой режим собран на этом: `Role=` в `native/native.ini` ставит игрока на
любую из девяти сторон, включая четверых — Корво, Дауда, Томаса и Билли.
Подробности — в `docs/FINDINGS.md`, раздел «Ролевой режим».

## С чего начать

### 1. Собрать данные с машины с игрой

```
python tools/harvest.py
```

Скрипт сам ищет игру в библиотеках Steam и типовых местах; если не нашёл —
`--game-dir "D:\Steam\steamapps\common\Dishonored"`.

Он складывает в `game-data/` копии всех конфигов, каталог секций и ключей и
манифест с параметрами экзешника. Это фундамент: без каталога имена ключей
приходится выдумывать, а игра неизвестный ключ молча игнорирует — режим будет
выглядеть рабочим, ничего не меняя.

**Результат не коммитится** — это содержимое игры, а не наша работа, и оно
перечислено в `.gitignore`. Каждый, кто работает над модом, запускает `harvest`
на своей копии. Подробности — ниже и в [game-data/README.md](game-data/README.md).

### 2. Собрать режим

Режим — это данные, а не код: JSON в `modes/` со списком правок конфигов.

```
python tools/modekit.py list
python tools/modekit.py validate iron-ghost
python tools/modekit.py apply iron-ghost
python tools/modekit.py restore
```

`apply` сохраняет текущие конфиги в `backups/`, накладывает правки и ставит
файлам атрибут «только чтение» — без него игра перезапишет их при запуске.
`restore` возвращает всё как было, байт в байт.

`validate` не пропустит правку, ссылающуюся на несуществующий ключ. Лежащий в
репозитории `iron-ghost` эту проверку сейчас намеренно не проходит: его ключи
помечены `unverified` и заполняются после первого `harvest`.

### 3. Нативный слой

Нужен для того, что конфигом не делается: состояние режима, счёт, выбор
персонажа. Сборка, установка и порядок снятия сигнатуры — в
[native/README.md](native/README.md).

## Устройство

```
docs/ARCHITECTURE.md   три слоя модинга, что каждый может и чего не может
tools/harvest.py       сбор конфигов и метаданных с установленной игры
tools/modekit.py       сборка, установка и откат режимов
tools/ue3ini.py        парсер конфигов UE3, сохраняющий форматирование
tools/test_ue3ini.py   его тесты
modes/                 описания режимов, по одному JSON на режим
modes/_schema.json     схема описания режима
game-data/             сюда harvest кладёт снятые данные
native/                нативный слой: ASI-плагин на C++
```

## Что попадает в репозиторий, а что нет

Правило одно: **в репозитории лежит только то, что написали мы. Файлы игры
остаются на диске у того, кто её купил.**

| | В репозиторий | Только локально |
|---|---|---|
| Инструменты, нативный слой, тесты | да | |
| Описания режимов — имена ключей и наши значения | да | |
| Документация | да | |
| Конфиги игры (`game-data/`) | | да |
| Пакеты `.upk` | **никогда** | |
| Декомпилированный UnrealScript | **никогда** — только патчи | |
| Извлечённые ассеты: модели, текстуры, звук | **никогда** | |

Граница проходит там же, где авторство. Строка вида `ManaRegenRate = 0.0` в
описании режима — это функциональный идентификатор и значение, выбранное нами.
Скопированный целиком `Player.ini` — файл, написанный Arkane.

Из этого же следует способ распространения: мод раздаётся как **инструмент плюс
описания режимов**, а не как готовые файлы игры. Игрок ставит его на свою копию,
и `modekit` правит его собственные конфиги, сохранив исходные в `backups/`. Ни
одного байта Arkane при этом не передаётся.

Отдельно стоит помнить: реверс-инжиниринг формально запрещён лицензионными
соглашениями почти всех издателей, и Bethesda не исключение. К некоммерческим
модам это на практике не применяют десятилетиями, но риск не нулевой, и он
заметно растёт, если брать за мод деньги или использовать официальный брендинг
так, будто мод одобрен издателем. Ни того, ни другого делать не стоит.

Это практические ориентиры, а не юридическая консультация.

## Тесты

```
python tools/test_ue3ini.py
cmake -B native/build-tests native/tests && cmake --build native/build-tests \
  && ctest --test-dir native/build-tests --output-on-failure
```

Первое проверяет, что правка конфига меняет ровно одну строку и не трогает
кодировку, переводы строк и комментарии. Второе — четыре набора нативного слоя:
разбор сигнатур и кодирование перехода, подбор раскладки объектов UE3, разбор и
планирование правок, таблица ролей.

Тесты собираются под хост, а не под Windows: проверяемая логика не трогает
`windows.h` ровно ради этого, и гонять их можно там, где игры нет.
