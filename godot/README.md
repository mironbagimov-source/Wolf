# Считалка — проект Godot

Godot 4.5. Основная версия игры: здесь и код, и сцены, и уровень — всё текстом
в репозитории, всё запускается и проверяется без редактора.

Дизайн — `../docs/GDD.md`.

## Просто поиграть

Собрать один самодостаточный файл — движок, код, модели и скины внутри:

```bash
godot/tools/build.sh              # обе платформы
godot/tools/build.sh Windows      # только одна
```

Получится `build/windows/Считалка.exe` и `build/linux/Считалка.x86_64`. Ничего
устанавливать не надо: скачал, запустил, играешь. Нужны шаблоны экспорта того же
выпуска, что и сам Godot (кнопка «Export templates» на
[godotengine.org/download](https://godotengine.org/download)).

## Запустить из исходников

```bash
godot --path godot                 # игра: меню → выбор гостя или убийцы → матч
```

Или открыть папку `godot/` в Godot Hub / редакторе и нажать Play. Первый запуск
из командной строки на чистом клоне может потребовать импорта:

```bash
godot --headless --path godot --import
```

## Проверить

```bash
godot --headless --path godot --fixed-fps 60 tests/smoke_test.tscn
```

Поднимает матч без интерфейса и без человека за рулём и прогоняет то, во что
играют: цепочку «сбил → на плечо → на крюк → строка считалки», срыв Трикстера,
плющ и поросль Ведьмы, таран сквозь стену и захват на ходу у Роджера, все три
добивания от первого такта до последнего, пять зон и их опасность, две ступени
квеста (три щита → ворота, два щита за воротами → пролом), черты выживших,
работу ботов на щитах и выход наружу. Ненулевой код возврата — что-то сломано.

## Инструменты

```bash
godot --headless --path godot --script tools/bake_world.gd -- catacombs
godot --headless --path godot --script tools/bootstrap_settings.gd # карта ввода и слои → project.godot
godot/tools/build.sh                                               # готовый билд
```

`bake_world` складывает одну зону из данных в обычную сцену `scenes/<зона>.tscn`:
открой её в редакторе, походи по ней, замерь расстояния. Зону, а не весь мир —
целиком это больше шестисот стен и сцена, которую незачем держать в репозитории.
Это снимок, а не источник правды: игра по-прежнему строит уровень из
`scripts/world_data.gd`. Поправил геометрию в редакторе — перенеси числа в
данные, иначе следующая выпечка затрёт правку.

`bootstrap_settings` нужен только когда меняется раскладка или слои
столкновений: сериализацию `InputEventKey` пишет сам движок, а не руки.

## Что где

```
scripts/
  world_data.gd     — мир как данные: пять зон, стены, проёмы, крюки, щиты, спавны
  nav_grid.gd       — сетка путей (волна по метровым клеткам)
  kits.gd           — весь баланс: черты гостей, три убийцы, добивания, считалка
  actor.gd          — общее тело: движение по намерению, взгляд, подсветка
  guest.gd          — состояния гостя, черта, ползание, крюк, взаимодействия
  killer.gd         — три набора сил в одном теле
  finisher.gd       — добивание: постановка в четыре-пять тактов
  guest_brain.gd    — бот-гость: убежать, снять с крюка, поднять, чинить, уйти
  killer_brain.gd   — бот-убийца: слух, погоня, ноша, патруль по зонам
  match_runner.gd   — матч: постройка мира, зоны, квест, таймеры, развязка
  body_skin.gd      — скин: цвета деталей и процедурный узор
  ui.gd             — меню, HUD, финальный экран
  main.gd           — склейка матча, интерфейса и мыши
skins/
  *.tres            — по скину на убийцу и на каждого гостя
scenes/
  main.tscn         — точка входа
tests/
  smoke_test.tscn   — прогон матча (см. выше)
  shot.tscn         — рендер кадров по зонам и добиваниям, для проверки глазами
tools/
  build.sh          — готовый к запуску билд
  bake_world.gd     — зона → редактируемая сцена
  blender_cast.py   — четыре тела на общем скелете → assets/cast.glb
```

## Почему навигация своя, а не NavigationServer3D

Поросль Ведьмы проходима для убийцы и непроходима для гостей — это два разных
графа над одной геометрией, и они меняются по десять раз за матч: заросли
вырастают и вянут, Роджер сносит стены. Метровая сетка с волной перестраивается
мгновенно, обслуживает обе стороны одним кодом и детерминирована — headless-тест
прогоняет ровно то же, что увидит игрок.

Мир в 220 на 190 метров она держит: выпечка не «каждая клетка спрашивает все
стены», а «каждая стена красит свои клетки», и на шестистах стенах это занимает
пару миллисекунд. Прямая видимость (`has_clear_path`) тоже считается по сетке —
грубее настоящей геометрии на полметра, зато не зависит от числа стен, а боты
дёргают её каждый кадр.

## Модели

Четыре тела в `assets/cast.glb`: гость, Трикстер, Ведьма, Весёлый Роджер.
Слеплены скриптом, а не скачаны:

```bash
blender --background --python godot/tools/blender_cast.py
```

Скрипт берёт скелет и анимации из `assets/soldier.glb` (Soldier из примеров
three.js, MIT — донор рига, в игре не появляется), выбрасывает его меши и
насаживает на кости свои: тонкий оборванец, арлекин в колпаке с серпом в руке,
балахон до земли с венцом из шипов, туша в парусине и якорной цепи.

Каждая деталь целиком привязана к одной кости — жёсткий скиннинг, отсюда
угловатость. Это осознанный лоу-поли: такой силуэт читается в тумане формой, а
не текстурой, и не требует ручной развесовки. Все четыре меша сидят на одном
скелете и лежат в одном файле, поэтому анимации не дублируются вчетверо: при
спавне игра оставляет нужный меш, остальные удаляет.

Правки формы — в `tools/blender_cast.py` (пропорции ролей собраны в четырёх
функциях `build_*`), после чего пересобрать `cast.glb`. Если файл не
загрузится, тела соберутся из капсул, чтобы матч оставался играбельным.

## Скины

Цвет и фактура живут не в модели, а отдельно — в `skins/*.tres`. Это обычные
ресурсы Godot: открываются в редакторе, правятся мышью, лежат в репозитории
текстом. Скин знает цвет каждой детали модели (`guest_cloth`, `trick_bone`,
`witch_thorn` и так далее — имена задаёт Blender-скрипт), какие детали
металлические, какие светятся в темноте, и каким узором всё это затёрто.

Узор рисуется кодом при загрузке (`scripts/body_skin.gd`): грязь, ромбы
арлекина, мох, ржавые потёки, переплетение парусины. Развёртки у моделей нет
вовсе, поэтому текстура кладётся трипланарной проекцией — движок проецирует её
с трёх сторон, и UV не нужны.

Скинов семь: по одному на каждого убийцу и по одному на каждого гостя. Разные
гости — не украшение: по тряпью в матче узнают, кого именно тащат на крюк и кого
ты сейчас поднимаешь с земли.

Завести заново или раздать правку всем сразу:

```bash
godot --headless --path godot --script tools/bake_skins.gd
```

Класс называется `BodySkin`, а не `Skin`: `Skin` занят самим движком, и своё
объявление молча проигрывает встроенному — на этом я уже один раз попался.

## Мир и добивания

Мир строится из `scripts/world_data.gd`: пять зон, у каждой свой вес опасности,
свой воздух (свет, туман, цвет пола) и свой генератор — сетка камер для
катакомб, россыпь стволов для джунглей, ряды домов для деревни. Всё это обычные
словари, поэтому столкновения, сетка путей, поросль Ведьмы и таран Роджера
работают с новыми зонами тем же кодом, что и со старым кварталом.

Добивания живут в `scripts/finisher.gd`: такты — данные в `Kits`, постановка —
код. Пока идёт добивание, оба тела помечены `pinned` и выключены из игры, а
камера игрока уходит на облёт. Всё нарисовано примитивами — цепь коробками,
побеги конусами, кровь квадратами: в тумане на трёх метрах этого хватает.

## Чего пока нет

- Звука. В браузерной версии он синтезированный; сюда не перенесён.
- Оружия в кадре от первого лица. В руке модели серп есть, но своё тело
  в виде от первого лица скрыто, так что игрок его не видит.
- Мультиплеера. В матче один человек и боты.
- Своего скелета и анимаций: они пока донорские, свои только тела.
